# 诗云连接与开发

> 诗云（Shiyun）是挂在个人文学知识库上的诗词可视化与赏析服务。纯 Node.js 标准库实现、零外部依赖、单测友好。本文档覆盖：系统架构、数据解析逻辑、数据源连接（本地文件 / Obsidian Local REST API）、LLM 接入、API 契约与二次开发指引。

---

## 1. 架构总览

```
┌─────────────────────────────────────────────┐
│                 浏览器 (index.html)          │
│   品 → 词云物理渲染    赏 → 赏析卡片+AI 生评 │
└──────────────────────┬──────────────────────┘
                       │ HTTP (localhost:8899)
┌──────────────────────▼──────────────────────┐
│              server.js (Node 标准库)         │
│  ┌─────────────┐ ┌───────────────────────┐  │
│  │ scanLocal() │ │  scanObsidian()       │  │
│  │ 直读文件系统 │ │  Obsidian REST API   │  │
│  └──────┬──────┘ └──────────┬────────────┘  │
│         └────────┬──────────┘                │
│            parseMd → poems[]                 │
│  ┌─────────────┐ ┌──────────────┐           │
│  │ scanReviews │ │  askLLM()    │           │
│  │ 赏析 frontmatter│ OpenAI 兼容 │          │
│  └─────────────┘ └──────────────┘           │
└──────────────────────┬──────────────────────┘
                       │
  ┌─────────────┐  ┌───▼────┐  ┌──────────────┐
  │ wiki/归档/诗集 │  │ config │  │ wiki/赏析/    │
  │ (frontmatter  │  │ .json  │  │ (poem/rating/ │
  │  + 正文)      │  └────────┘  │  best_line)   │
  └─────────────┘             └──────────────┘
```

- 数据流单向：文件系统 / Obsidian API → server → 浏览器，无写入路径（config 除外）
- 读取路径都是相对 `__dirname` 上一级（假设诗云目录位于文学库根目录下）

## 2. 核心模块与解析逻辑

### 2.1 `parseMd(text)` — frontmatter 解析

```js
const m = t.match(/^---\r?\n([\s\S]*?)\r?\n---\r?\n?([\s\S]*)$/);
```

- 简单 key: value 逐行解析，自动剥掉引号
- 返回 `{ fm, body }`，`fm` 直接对应 frontmatter 字段（title / year / lang / theme / form / created）

### 2.2 `poemLines(body)` / `poemStanzas(body)` — 正文切分

```js
// lines：去掉空行、[[嵌入]]、```代码块、# 标题、<!--注释-->、--- 分隔线
// stanzas：按 \n[ \t]*\n 双换行切段，每段再走 poemLines
```

- `lines`（逐行）与 `stanzas`（分段）都会发给前端
- **前端「赏」按 `form` 决定用哪个**：
  | form | 展示片段 |
  |------|---------|
  | 近体诗 | 按**行**取整句（含逗号一行） |
  | 词 / 现代诗 / 英文诗 | 按**空行分段**取整段 |
  | 随吟 | 按段取整句 |
  | 无 form | 前端自动推断 |

### 2.3 `scanLocal()` — 本地文件数据源

- BFS 遍历 `../wiki/归档/诗集/`
- 年份从 `created` 字段的 `20\d{2}` 提取，回退到路径中的 `\20xx\`
- 去重键：`title|lang|首行`——主题维度与年份维度各有产物，只保留第一份
  ```js
  const k = x.title + '|' + x.lang + '|' + x.lines[0];
  ```

### 2.4 `scanReviews()` — 赏析数据源

- 遍历 `../wiki/赏析/*.md`，取 frontmatter 的 `poem / theme / rating / best_line` + 正文
- 前端用它关联诗歌（`poem` 字段 ↔ 诗歌 `title`）

## 3. 数据源连接

### 3.1 本地直读（默认行为）

无需任何配置。只需保证目录结构：

```
文学库/
└── wiki/
    ├── 归档/诗集/     # server.js 的 ROOT
    └── 赏析/          # server.js 的 REVIEW_DIR
```

### 3.2 Obsidian Local REST API（可选实时源）

读取 Obsidian 监测目录下的 `.obsidian/plugins/obsidian-local-rest-api/data.json`：

```js
function obsidianInfo() {
  const d = JSON.parse(fs.readFileSync(
    path.resolve(__dirname, '..', '.obsidian', 'plugins', 'obsidian-local-rest-api', 'data.json'), 'utf8'));
  return { key: d.apiKey || '', port: d.insecurePort || 27123, available: !!(d.apiKey && d.enableInsecureServer) };
}
```

接入步骤：
1. Obsidian 安装 **Local REST API** 插件并启用
2. 插件设置里开启 `Enable Insecure Server`（默认端口 27123），复制 API Key
3. 服务启动时自动探测：`available=true` 则视为可用
4. 数据源策略（`/api/poems?source=` 或 `config.json` 的 `source`）：
   - `auto`（默认）：先试 Obsidian，失败回落本地
   - `local`：强制本地
   - `obsidian`：强制 Obsidian，失败返回 502

Obsidian 端用 BFS 抓取：`/vault/wiki/` 起步，`name.endsWith('/')` 判目录入队，过滤 `归档/诗集` 下的 `.md`，再逐个拉正文；每次抓取结果缓存 30 秒（`obCache`）。

## 4. LLM 接入（AI 即时生评）

### 4.1 协议

OpenAI Chat Completions 兼容（`POST {base}/chat/completions`），支持 DeepSeek / 通义 / Moonshot 等。

### 4.2 配置

```json
{
  "source": "auto",
  "author": "你的笔名",
  "llm": { "base": "https://api.deepseek.com", "key": "sk-xxx", "model": "deepseek-v4-pro" }
}
```

或网页端「配置」面板动态填入（POST `/api/config` 持久化到 config.json）。`author` 字段用于 AI 赏析提示词中的称呼（见 4.3），留空则显示占位符 `XXX`。

### 4.3 提示词要点（server.js `askLLM`）

- 以 `config.json` 的 `author` 作为助手身份称呼（如「你是{author}的文学赏析助手」），未配置则用占位符 `XXX`，由使用者自行填写
- 要求中文 250 字以内、凝练典雅
- 输入：诗题 / 年份 / 主题 / 全诗 / 所选诗句（picked）
- 可选附带既有赏析，要求「精炼化用，不要照抄」
- 60 秒超时（AbortController），`max_tokens: 4000`
- 兼容推理模型：若 `reasoning_content` 非空或 `finish_reason === 'length'`，给出友好错误提示

### 4.4 请求体

```json
POST /api/ask
{
  "poem": { "title": "边城月", "year": "2023", "theme": "情", "text": "…", "picked": "爱恨摇年华已悄" },
  "llm": { "base": "...", "key": "...", "model": "..." }   // 可选，覆盖全局配置
}
```

## 5. API 契约

| 端点 | 方法 | 入参 | 返回 |
|------|------|------|------|
| `/api/status` | GET | — | `{source, author, obsidianAvailable, llmConfigured, llm:{base,model,keySet}}` |
| `/api/poems` | GET | `?source=local\|obsidian` | `{source, total, poems:[{id,title,year,lang,theme,form,created,lines[],stanzas[][]}]}` |
| `/api/reviews` | GET | — | `{total, reviews:[{poem,theme,rating,best_line,body}]}` |
| `/api/config` | POST | `{source?, llm?}` | `{ok:true}` |
| `/api/ask` | POST | `{poem, llm?}` | `{text}` |

静态资源：`/` → `index.html`；MIME 表覆盖 html/js/css/png/jpg/svg；路径穿越已用 `normalize + startsWith` 防住。

## 6. 前端（index.html）

单文件 707 行，无构建、无框架，逻辑分两屏：

- **品（词云）**：`data/poem-words.json`（2517 词，chinese-poetry 全宋词语料高频词 + PMI 互信息筛选）优先命中；未命中回退二元组合（相邻两字）。词云渲染到 `<canvas>`，字形以 `assets/诗字剪影.png` 为剪影
- **赏（赏析）**：配对 `reviews` 与 `poems`；无赏析作品可点「AI 生评」调 `/api/ask`；片段按 `form` 选取（见 2.2 表）；`best_line` 优先展示
- **配置**：source 切换、LLM 三参数，POST 到 `/api/config`

## 7. 二次开发指引

### 7.1 本地跑通

```bash
cd 诗云
node server.js          # http://localhost:8899
```

### 7.2 修改建议入口

| 想改什么 | 改哪里 |
|---------|--------|
| 词云分词更准 | `data/poem-words.json`（追加自定义词条）；算法在 index.html 分词函数 |
| 新数据源（如 GitHub Pages / 飞书表格） | server.js 仿照 `scanLocal` / `scanObsidian` 新增 scanXxx，收敛到同一个 poems[] 结构 |
| 赏析片段选取规则 | 前端 `form` 分支（近体诗=行 / 其他=段 / 随吟=句） |
| LLM 提示词 / 单次生评 | `askLLM()` |
| 端口号 | `server.js` 顶部 `const PORT = 8899` |

### 7.3 代码风格约定

- 纯 Node 标准库（http / fs / path / url），不引入任何依赖——这是本项目的硬约束
- 解析函数（parseMd / poemLines / poemStanzas）为纯函数，可直接单测
- frontmatter 解析保持简单：单行 `key: value`，值剥两端引号

## 8. 常见问题

**Q：启动后「赏」一片空白？**
检查 `wiki/赏析/` 是否有文件，且 `poem` 字段与 `wiki/归档/诗集` 中诗歌的 `title` 完全一致（中文全角标点也要一致）。

**Q：Obsidian 数据源报 502？**
插件未启用 / 未开 `Enable Insecure Server` / API Key 过期。`/api/status` 会告诉你 `obsidianAvailable`。

**Q：词云总把两个字拆开？**
词典未命中该词。向 `data/poem-words.json` 的 `words` 追加即可（前端优先按词长命中）。

**Q：AI 生评报「模型把 token 全用在思考上了」？**
用的是推理模型且未配足够 `max_tokens`。换非推理模型，或调大 `askLLM` 中的 `max_tokens`。

**Q：想部署到公网？**
默认只监听 localhost。请勿直接暴露 8899 端口到公网（config.json 含 API Key）；建议内网使用或自行加鉴权。
